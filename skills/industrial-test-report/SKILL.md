# Industrial Test Report

## 适用
功能测试报告、性能/稳定性评估、视觉准确率测试、工厂验收 FAT、现场验收 SAT、故障复盘、版本发布评估。

## 强制前提
先确定被测软件 commit/版本、测试工位、硬件型号/序列号（公开报告脱敏）、相机/镜头/光源/标定版本、环境、测试日期与测试人员。无法获取时标注未提供，不能补假数据。

## 用例与证据
1. 从需求生成 ID → 测试项 → 前置条件 → 步骤 → 预期结果 → 实际结果 → 判定 → 证据链接。
2. 结果值仅用 PASS/FAIL/BLOCKED/NOT RUN/PENDING_REVIEW 五类，中文分别写作 通过/失败/阻塞/未执行/待复核；已执行但证据不足应为 PENDING_REVIEW，不是 PASS。
3. 视觉：按明确口径统计 TP/FP/TN/FN、误检/漏检、重复定位误差、不同工况覆盖；保留分母、样本集、阈值、置信区间（适用时）。
4. 性能：区分均值、P95、P99、最大值；注明采样周期、样本数、预热、CPU/设备配置。
5. 设备：高低电平触发、断线、重连、看门狗、超时、急停、设备反馈、异常恢复、冷启动/热重启、持续运行。
6. 缺陷关联 Issue/日志/照片/视频时间戳；写修复提交、复测环境和结果。
7. 对留存风险给出放行建议与责任审批，不能用文档报告取代现场签字。

## 报告结构
见仓库根目录 templates/test-report.md。包含执行摘要、环境、用例矩阵、测量数据、异常、风险、结论、签字与附件。

## 交付校验
核对数量、百分比、单位与总计是否一致；删除示例值；区分正式签署和拟签署字段；检查敏感数据是否可外发。
