# Industrial Code Review

## 证据优先
先读实际文件、提交/差异、运行路径、调用方和测试；不能凭项目名称推断实现，也不能将建议说成已确认缺陷。对用户只展示有根据的可操作发现。

## 风险排序
- P0：可能造成危险运动、物理损坏、跳过安全动作、误判导致失控、假成功持续生产。
- P1：竞态、析构 UAF、结果跨周期串扰、异常未停机、重启失效等高概率生产故障。
- P2：可维护性、接口缺口、性能和非关键错误处理。
优先级由影响、触发条件与现有保护共同决定，勿一律抬高。

## 审查清单
- 生命周期：后台 detached thread、捕获 this、SDK 句柄释放、Qt 跨线程信号、锁顺序与死锁。
- 状态机：重复触发、高电平上电、停机-启动切换、复位后计数与错误状态。
- 数据：索引越界、单位/坐标系不一致、快照有效期、跨周期 stale result、图像/配置版本绑定。
- 设备：写 IO 回执与设备反馈分离、熔断、持续失败、假连接、超时/重连/降级。
- 算法：错误吞没、极端样本、模板重复匹配、标定失效。
- 可观测性：失败时必须保留可定位的错误码、日志、trace/周期 id。

## 输出格式
每个发现给出：严重等级、文件+行/函数、触发条件、现象与后果、证据、最小修复方案、回归用例。未定位到文件时标注“待核实”，不要杜撰行号。

## 闭环
先写复现/探针 → 最小修复 → 静态检查/编译 → 单测/集成 → 明确现场未测项 → 变更记录。测试命令及日志才可作为 PASS 证据。
